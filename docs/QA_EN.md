# English Q&A

**What is new here?**
The complete loop connects behavioral context to cumulative content controls, durable enforcement and independently inspected delivery. The demonstrated value is this auditable loop, not an accuracy claim.

**Is this an LLM wrapper?**
The offline lab runs a genuine Isolation Forest, deterministic content detectors, SQLite transactions and actual loopback HTTP. The portal sends admitted requests to a real local Qwen/llama.cpp CPU model or the explicitly selected OpenAI Responses API. The local model returned live answers; the OpenAI account returned 429, so no successful cloud answer is claimed. Its returned answers do not replace the security engine. AI assisted development, as disclosed in AI_ASSISTANCE.md.

**Is the receiver external?**
The original receiver is an authorized loopback listener with its own receipt database and produces no AI answer. The portal has returned real local Qwen answers and can use OpenAI when the API account is available. Its model response ID is gateway-observed evidence, not the local receiver receipt or independent attestation of input delivery.

**How does behavior change the result?**
Six actual protected-document accesses in 120 seconds activate a separate 80/100 lab rule. Three blocked attempts activate 85. The server takes the maximum of the live rule and dated completed-day score. This tightens controlled-excerpt limits, without pretending to retrain the IF or estimate malicious intent.

**Can low behavior allow a secret?**
Recognized structured credentials and confirmed restricted material are unconditional hard blocks, including at zero behavior. Only controlled-excerpt allowances depend on context.

**Are two or three words enough?**
A source-anchored short sequence or bounded co-occurrence of multiple distinctive source tokens can establish evidence. Generic single words do not. Supported evidence accumulates without concatenating unrelated requests. Source registration and declared normalization bound coverage.

**What about insertion, reordering and Cyrillic letters?**
Executed regressions cover inserted words, reordered distinctive tokens and supported TR39 confusables. Mixed scripts alone do not block. This is not universal semantic or visual attack coverage.

**What does 24.73% mean?**
Distinct eligible normalized source 4-grams divided by the source's eligible distinct 4-grams. Anchored tokens have a separate denominator and threshold. Neither ratio measures bytes reconstructed.

**Does a daily drip bypass policy?**
Both 24-hour and 30-day windows apply. Daily drip regressions hit the long-window limit after short-window expiry. Confirmed exposure eventually ages out of finite windows. Unknown delivery remains conservatively counted until reconciliation. There is no lifetime or cross-identity guarantee.

**What if requests race or retry?**
SQLite serializes admission and reserves exposure first. One durable claim permits one send. Gateway and receiver bind payload identity. The UI retains its pending key after transport failure for unchanged input.

**Does timeout mean successful prevention?**
No. The receiver can accept before acknowledgement is lost. DELIVERY_UNKNOWN stays budgeted. Reconciliation validates the original receipt without another send. Receipt absence alone cannot prove non-delivery.

**What did CERT show?**
V1 failed: 0 TP among 476 incident-associated positive test days. The original artifacts remain. V2 adds device/logon/HTTP/file calendar days and exact actor/channel/ID/time-qualified labels. Read its actual saved result if execution completed. The release was already inspected, so v2 is development evidence. Changed population and labels prevent a direct like-for-like improvement claim. CERT itself is synthetic research data.

**How do you prevent label leakage?**
Personal and peer references use earlier days only. Training precedes validation and evaluation. Labels never enter features, fit, baselines or threshold selection. Tests perturb labels, future events and same-day peers to verify invariance. Cold-start days and no-signal incidents remain explicit in coverage.

**What is the false-positive rate?**
We report actual benchmark workload and local benign regression controls. Neither establishes a real organization's rate. A shadow-mode pilot with data owners must measure it before enforcement.

**What is stored?**
Gateway hashes, matched evidence, context and transitions. Fingerprints are not anonymous. The receiver retains full synthetic payloads until reset and masks analyst previews. The portal caches AI output/response metadata until reset for safe retries; output can repeat input text. API keys stay in server memory. Runtime databases are excluded from packages. Production retention needs separate review.

**Is authentication production-ready?**
The identity selector is simulated. CSRF, loopback origin checks, employee scoping, server-derived context and receiver authorization are implemented. Enterprise SSO and provider tenant enforcement remain future work.

**What remains outside scope?**
Traffic bypassing the application, semantic paraphrases, images/OCR, arbitrary/nested encoding chains, cross-identity collusion and production deployment of the opt-in OpenAI route. This is a bounded local prototype. The API key is memory-only; cached AI output is local and cleared by demo reset. A timeout never triggers an automatic resend. Read AI_PORTAL.md and actual live evidence before claiming provider success.
