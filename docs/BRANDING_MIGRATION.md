# SEDRA 0.9 naming and repository scope

The Python package/import path is now `sedra`; start with `python -m sedra.app`. Launchers, synthetic secret examples, internal identifiers, environment variables, session/receiver headers, download names and the local model alias consistently use SEDRA. Supported Python remains 3.12. The registered synthetic corpus is version 3 because branding changes its source bytes and public-reference exclusions.

Presentation slides, PPTX, speaker/Q&A material, old screenshots and the superseded embedded source ZIP are excluded from the current GitHub tree and packages. Earlier Git commits remain history. Local materials were retained privately; the application no longer serves a presentation route.

Historical JSON report identifier keys, names, aliases and displayed source paths were normalized for the requested branding. **This is metadata normalization, not a rerun of those experiments.** `artifacts/branding_migration.json` records original and normalized file hashes. Original artifact bytes and the pre-migration Git bundle remain in the ignored local work directory. Numeric measurements, original payload/source hashes and the trained original model were not rewritten as new results. Those original digests refer to original historical input bytes, not renamed display strings.

The original failed file-only CERT outcome remains 0 TP / 476 positive test user-days; multichannel v2 remains unmeasured. Published metadata copies are no longer byte-identical to the original reports. Earlier unchanged-byte statements describe their earlier recorded builds; use the migration map for the current repository. Freshly executed 0.9 regression/live reports identify their actual new execution separately.

Existing private runtime ledgers are preserved locally and are not rewritten to change historical deliveries. New demonstration activity uses a separate runtime directory so renamed source versions and new session identifiers cannot be confused with old admissions.
