# Multichannel experiment and the next independent gate

The frozen v2 development protocol is `artifacts/cert_v2_protocol.json`; its implementation is `scripts/cert_multichannel.py`. Do not overwrite or rename the original failed file-only v1 artifacts.

V2 consumes complete, integrity-verified device/logon/HTTP/file sources, dated LDAP membership and actor/channel/original-ID/timestamp-qualified answer observables. It constructs calendar days with explicit source coverage and limited-history fallback, retains no-signal incidents in coverage, compares personal rules, peer rules, IF and their declared combination, and freezes thresholds on validation without labels.

A v2 report is measured only after actual extraction, ingestion and execution. While pending, the UI disables that source. Its result, when available, remains **development on previously inspected r4.2**. Expanded sources and changed labels prevent a direct like-for-like improvement claim over v1. Current execution status and exact values belong to STATUS.md and the saved JSON report.

The next independent gate requires a genuinely untouched release or prospective pilot. Freeze the feature/schema/label and threshold protocol before inspecting its final holdout. Report source coverage, cold-start days, prevalence, TP/FP/FN, achieved alert load, false-alerted actors, coverage-adjusted incident/actor recall and delay. Do not relabel another subset of already-inspected r4.2 as an untouched test.

The first enterprise pilot should add real identity and provider controls, collect consented telemetry in shadow mode and have data owners validate false positives and handling policy before enforcement. Hard content prohibitions stay independent of anomaly triage budgets.
